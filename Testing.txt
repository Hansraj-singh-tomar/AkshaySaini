* Library's needed for Unit and Integration Testing - 

1. React Testing Library - This is builds on top of DOM Testing Library by adding APIs for working with React Components.
2. JEST - Jest is a delightful JavaScript Testing Framework with a focus on simplicity.

Note - React Testing Library uses a Jest behind the scene. 

* Setting up Testing in our app
1. Install React Testing Library -> npm install --save-dev @testing-library/react
2. Install Jest -> npm i -D jest
3. Install Babel-jest -> npm install --save-dev babel-jest @babel/core @babel/preset-env
4. Configure Babel, babel.config.js ->   module.exports = {
                            presets: [['@babel/preset-env', {targets: {node: 'current'}}]],
                        };
5. Configure Parcel config file to disable default babel transpilation - With that our parcel default babel configration will be disabled
    .parcelrc: {
                    "extends": "@parcel/config-default",
                    "transformers": {
                        "*.{js,mjs,jsx,cjs,ts,tsx}": [
                        "@parcel/transformer-js",
                        "@parcel/transformer-react-refresh-wrap"
                        ]
                    }
                }
6. Jest configration - npx jest --init (npx means we are just executing jest) 
7. Install JSDOM library - npm install --save-dev jest-environment-jsdom
    - If you're using Jest 28 or later, jest-environment-jsdom package now must be installed separately.
8. Install @babel/preset-react - to make JSX works in test cases
9. Include @babel/preset-react inside my babel.config.js file => @babel/preset-react will helps to testing library to convert JSX into normal html code, so that it can read properly
module.exports = {
    presets: [
        ['@babel/preset-env', { targets: { node: 'current' } }],
        ['@babel/preset-react', { runtime: "automatic" }],
    ],
}; 
10. Install npm i -D @testing-library/jest-dom - we are getting an error toBeInTheDocument is not a function, that why we have to install this package.

Note - Parcel uses babel behind the scene and we are trying to configure babel according to us.
        Their is conflict between babel and parcel, parcel says i have my own babel configuration 
        and i have added this babel configuration, this is kind of override existing babel configuration which is parcel has set for us

* Command to run test cases - npm run test

* jsdom(browser-like) - When you run test cases their is no server running/their is no browser, so they will need a environment to run it. where this testing code will be executed / where this test cases will be excuted. for that we use jsdom.
  JSDOM - JSDOM is a library which parses and interacts with assembled HTML just like a browser. It's not a browser, it's like a browser.


* __tests__ => inside it all .js and .ts file consider as a test file, 
                Headers.test.js, Headers.test.ts, Headers.spec.js, Headers.spec.ts file also consider as a test file.

Note - dunder = __, That is why we can call dunder test to our __test__ folder
